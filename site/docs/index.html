Instalacja

Wymagany jest macOS 14 lub nowszy oraz główne konto uprawnione do użycia sudo. Jeden instalator działa na Apple Silicon i Intelu.

  1. Pobierz instalator macOS i otwórz plik .pkg.
  2. Przejdź przez instalator systemowy.
  3. Otwórz Finder → Aplikacje → Agent Workbench.

Instalator umieszcza aplikację w /Applications. Nie tworzy kont i nie zmienia uprawnień Twoich katalogów. Xcode i rozpakowywanie ZIP-ów nie są potrzebne.

Pierwsza konfiguracja

W aplikacji wybierz Skonfiguruj Maca. Otworzy się Terminal z pytaniami. Nie musisz wpisywać komend.

  1. Potwierdź utworzenie standardowego konta agent, jeśli jeszcze nie istnieje. macOS poprosi o nowe hasło dla tego konta.
  2. Przygotuj folder projektów /Users/Shared/AgentWork i dostęp do niego.
  3. Przejrzyj propozycję ochrony głównego katalogu domowego. Zgoda zamknie agentowi dostęp do całego tego katalogu.
  4. Potwierdź instalację Codex i Claude w katalogu domowym użytkownika agent.

Pytania wymagają wpisania YES lub INSTALL. Istniejące konto agent i jego hasło zostają zachowane. Do konfiguratora możesz wrócić w Ustawieniach aplikacji.

Logowanie do narzędzi

Po konfiguracji wróć do aplikacji. Wybierz Zaloguj Codex albo Zaloguj Claude i wykonaj instrukcje narzędzia w Terminalu.

Każde narzędzie ma własne logowanie i zasady rozliczeń. Aplikacja nie kopiuje kluczy ani sesji z głównego konta. Przyciski logowania znajdziesz także w sekcji Agenci.

Pierwszy projekt

  1. Przejdź do sekcji Projekty i wybierz Dodaj projekt.
  2. Wskaż istniejący katalog wewnątrz AgentWork albo wybierz Izolowana kopia repozytorium i zaufane repozytorium źródłowe.
  3. Wybierz projekt, a następnie Uruchom Codex, Uruchom Claude lub Terminal.

Izolowana kopia zawiera zatwierdzoną historię Git. Nie przenosi niezapisanych zmian ani konfiguracji poświadczeń. Zmiany nie synchronizują się automatycznie z repozytorium źródłowym.

Stan sesji i błędy pojawiają się w szczegółach projektu. Przycisk Zatrzymaj wysyła SIGTERM; procesy uruchomione w tle niezależnie od sesji mogą wymagać osobnego zakończenia.

Uprawnienia i bezpieczeństwo

Agent działa jako standardowy użytkownik macOS. Hasła są obsługiwane przez macOS i sudo; aplikacja ich nie przechowuje. Konto agent nie otrzymuje praw administratora.

Wersja alpha nie ma certyfikatu wydawcy ani notaryzacji Apple. Jeśli system zablokuje plik, po próbie otwarcia przejdź do Ustawienia systemowe → Prywatność i ochrona. Jeśli ufasz projektowi, wybierz „Otwórz mimo to”. Instrukcja Apple.

Oddzielne konto nie jest pełnym sandboxem. Rzeczywisty dostęp wynika z uprawnień macOS; profile Safe i Network nie blokują sieci. Projekt nie przeszedł niezależnego audytu bezpieczeństwa.

Rozwiązywanie problemów

  • Brakuje Codex lub Claude: ponownie otwórz konfigurator i wybierz instalację narzędzi, a potem rozpocznij nową sesję.
  • Agent ma dostęp do prywatnych katalogów: uruchom konfigurator i przejrzyj opcję ochrony głównego katalogu domowego.
  • Brak zapisu w starszym projekcie: konfigurator nie zmienia rekursywnie istniejących plików. Utwórz nową izolowaną kopię lub przejrzyj uprawnienia.
  • Status jest nieznany: diagnostyka może wymagać uwierzytelnienia w Terminalu. Szczegóły znajdziesz w sekcji Agenci.

Szczegółowa instrukcja i komendy diagnostyczne

Aktualizacje i usuwanie

Pobierz nowy instalator i uruchom go. Aplikacja w /Applications zostanie zaktualizowana; konto agent, projekty i ustawienia pozostaną zachowane.

Jeśli starszą wersję instalowano w ~/Applications, otwórz nową kopię z systemowego folderu Aplikacje. Starsza kopia nie jest automatycznie usuwana.

Aplikację możesz przenieść do Kosza. Nie usuwa to konta agent, narzędzi, projektów ani uprawnień dodanych podczas konfiguracji. Instrukcja wycofania pozostałych zmian.
